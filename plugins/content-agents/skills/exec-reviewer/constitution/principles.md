# Review principles

Status: draft v0.1.0, built from the brand voice guide and messaging guide. Exec reviewers will refine these.

## What great looks like

- **PRI-001 Open in the reader's problem.** The first lines name a specific, real problem in the reader's own words, not CData's category label. Buyers say governance, control, MCP sprawl, token cost, and data leakage; they rarely say "AI gateway" first.
- **PRI-002 System before outcome.** Every benefit is preceded by, or immediately grounded in, the mechanism that produces it. Benefits without architecture read as aspiration.
- **PRI-003 One message to land.** The piece has one clear thing it is trying to say. If you can't state it in one sentence after reading, that's a top issue.
- **PRI-004 Every section does new work.** If a section can be removed without breaking the argument, it's underperforming.
- **PRI-005 Value is specific to CData.** If a value statement could be pasted into a competitor's copy unchanged, it's empty.
- **PRI-006 Trust through resolution.** CData resolves access, structure, and meaning before the model runs. Never imply the AI "figures out" structure or that meaning emerges downstream.
- **PRI-007 Match the number to the room.** Use the proof point that matters to this audience (see `messaging.md`), not every number available.
- **PRI-008 End when done.** The last sentence is the strongest one, not a recap.

## What execs care about most (in order)

1. Is the message right and on-strategy? (messaging, positioning)
2. Is it accurate? (names, numbers, claims)
3. Is it clear to this audience? (structure, jargon budget)
4. Does it sound like CData? (voice)
5. Is it polished? (style, formatting)

Rank top issues in this order when severity is equal.
